# OVERSEE Reference Implementation

This repository contains an executable reviewer-facing implementation of OVERSEE for industrial asset-management decision support.

The repository integrates the existing OVERSEE logic, the original Digital Factory scenario pipeline, and the original testing/comparison environment into a clean public-facing structure aligned with the current paper terminology.

## Current implementation status

The current implementation is no longer the provisional scaffold. The provisional scaffold has been archived under:

```text
paper_artifacts/provisional_scaffold_archive/
```

The active implementation now uses migrated and refactored working logic under the `src/oversee/` package.

## What the demo does

The reviewer-facing demo executes the following flow:

```text
Digital Factory scenarios
â†’ OVERSEE input candidates
â†’ deterministic anchor recommendations
â†’ live generative path recommendations

```

The main command is:

```powershell

```

By default, this command runs in offline-safe mode. It removes `OPENAI_API_KEY` from the local process before execution. This means the live generative path is expected to activate safe fallback behavior instead of calling an external model.

## Current offline result pattern

In the validated offline reviewer run, the expected pattern is:

```text
case_count: 3
action_differences: 0
priority_differences: 0
rationale_differences: 3
live_generative_fallback_count: 3
live_generative_model_response_count: 0
```

Interpretation:

- the Digital Factory produces three executable cases;
- both recommendation paths are executed for the same cases;
- the live generative path does not call an external model in offline-safe mode;
- the live generative path falls back safely;
- action and priority remain aligned with the deterministic anchor during fallback;
- rationale differs because the live generative path records the fallback chain and execution context.

This is not a claim that the live generative path is universally superior. It is a traceable execution showing how OVERSEE exposes deterministic and generative recommendation paths under governance constraints.

## Useful commands

Run the deterministic anchor smoke test:

```powershell
$env:PYTHONPATH = "src"
python scripts\run_deterministic_anchor_smoke.py
```

Run Digital Factory through deterministic anchor:

```powershell
$env:PYTHONPATH = "src"
python scripts\run_digital_factory_deterministic_anchor_smoke.py
```

Run Digital Factory through live generative path in offline mode:

```powershell
$env:PYTHONPATH = "src"
python scripts\run_digital_factory_live_generative_path_offline_smoke.py
```

Run deterministic-versus-generative comparison:

```powershell
$env:PYTHONPATH = "src"
```


```powershell

python -m pytest tests\oversee -q
```

## Terminology rule

The clean repository uses current OVERSEE terminology only. Legacy experiment terminology must not appear in public-facing code, outputs, documentation or paper text.

Current public terms include:

| Current term | Meaning |
|---|---|
| `deterministic anchor` | Deterministic baseline recommendation path. |
| `model-backed anchor` | First model-backed recommendation support path. |
| `grounded model path` | Model-backed path with retrieved evidence context. |
| `live generative path` | Final live generative recommendation path with fallback behavior. |
| `deterministic-versus-generative comparison` | Comparison of deterministic and live generative outputs over the same Digital Factory cases. |

## Limitations

The repository currently validates an offline-safe execution mode. In this mode, external model execution is intentionally disabled and fallback behavior is expected.

The current implementation should be interpreted as an executable reviewer-facing reference package, not as a production deployment, a full CMMS/EAM integration, or a claim of universal performance superiority.
